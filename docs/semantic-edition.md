# Semantic Edition: 2026-09-28 R8 recovery and Debug snapshot

## Provenance and scope

This snapshot continues the maintainer-selected GPT6 r6 plain-language-enhanced baseline on `semantic-edition`. The previous `semantic-2026.09.24-r6` tag is retained unchanged. Complete current files are frozen at `semantic-2026.09.28-r8-debug`. The intervening 2026-09-25 local candidate was not separately pushed. This is a separate branch, not a V10/Deliberative judging-architecture merge.

The SC criteria, source-roster mechanism, score logic, report structure and ten core execution units are retained. The changes since r6 include the bilingual interface, scrolling-layout repair, restored backgrounds, explicit final-assessment/review duties, R8 recovery and Debug export described below. No debate-specific rule or predetermined winner was added.

## R8 and interface changes

- Runtime metadata (`inputHash`, schema/prompt versions, model snapshot) is bound by the host for the current response instead of being copied by the model. The model generates card content.
- Matching private drafts from the previous prompt version can resume as unapproved candidates only after the outer input/model/version binding is checked. A pre-migration copy is retained. Public imports and approved caches are still checked strictly; semantic approval is not migrated.
- An anchor's valid source reference need not be duplicated in `evidence`. Invalid sources and quotations remain errors; representativeness and meaning remain independent review duties.
- Guide text length is advisory in both original and plain-language cards. Required qualifications are not removed to meet an arbitrary word count. The independent semantic and readability reviews still apply.
- Normal continuation reuses a valid draft; explicitly restarting from R8 regenerates that stage. Valid upstream work can be reused, but a saved substantive objection can trigger a bounded review of the responsible upstream stage and regeneration of affected outputs. Continuation therefore does not guarantee R8-only API use.
- Chinese/English switching changes interface text only. The running-status panel now scrolls with the page instead of overlapping telemetry. Existing report structure and controls remain intact.
- The two background images are generated by the project with local ComfyUI, as confirmed by the maintainer. Their earlier exclusion as unresolved third-party artwork was an incorrect classification and has been corrected. Full images and embedded HTML are included under the maintainer's MIT publication authorization.

## Final assessments and substantive objections

An initial S3 registration and a later S7 assessment can differ for legitimate source-grounded reasons. Previously, C6 was instructed to use S3 weights while drawing decisions and summaries from S7, potentially mixing incompatible stages. S7 now makes the final per-clash assessment explicit in its existing table or associated reasoning; a justified revision can replace the initial registration. Tables, summaries and score explanations use the same reviewed assessment. Counts check presentation consistency; they do not determine importance, SC effectiveness or the winner.

R3 and R4.5 examine specific supporting judgments, not merely whether the winner direction agrees. R8 remains a review of the explanation. When it finds an upstream issue, orchestration asks the model to examine the original transcript and available artifacts, distinguish a note from a substantive correction or unresolved issue, and select the responsible existing stage. A problem visible in R6 HTML is not automatically a rendering-stage problem. Recovery preserves old artifacts, regenerates current prompts and follows existing dependencies, with checkpointed decisions and bounded retries. Continued substantive objections remain explicit rather than being repeatedly re-voted away.

## Diagnostics and interface notices

New-run and resume messages identify the actual entry path. Export Debug beside the run log collects current-session files, available reports, complete captured UI logs, metadata, persisted checkpoints/versions and associated Flight evidence. It preserves memory and durable snapshots separately, lists missing/partial evidence and redacts credential fields and known configured key values. Export does not mutate Judge/Flight state or call a model. It is an observation, not a new semantic approval or an atomic checkpoint across all stores.

The bilingual welcome page carries the maintainer-specified recent-use figures (450K–600K tokens and 45–90 minutes), variation/AI-error notices and endpoint cautions. These are user-facing reference figures, not a newly measured cross-model benchmark or resource guarantee from this packaging run. The warning about repeated runs producing different outcomes is descriptive, not a new randomness or scoring setting.

The [source inventory](source-inventory.json) records file origins. Complete files are included, not references to inaccessible originals. Private preparation keeps original complete files and a full comparison; those records are unnecessary to build the public repository.

Release inspection also found that an earlier embed rebuild had kept an obsolete second copy of the assets after the controller. This snapshot removes those duplicate copies, makes the embedder handle both historical placements, and checks unique block counts and idempotent rebuilding. All seven round-prompt templates and bundled executable modules are unchanged by that cleanup. The result contains one controller and 34 asset blocks, mirrored identically across the three Skill files.

## Known inherited failures

Reproduced in both the unmodified r6 source and this public copy; the default runner reports them.

1. `tests/self-check.test.js`: three negative terminology cases mutate old strings no longer defining active semantics. The previously failing duplicate/layout assertion is addressed by the packaging cleanup; the terminology cases still fail.
2. `pipeline-controller.js self-check`: includes the same legacy terminology checks and therefore still reports failure. Current embedded integrity, mirror, unique-block and CSS-source checks are verified separately; this does not turn the entire legacy check into a pass.
3. `tests/key-engine.test.js`: four failures concerning legacy patchKeys representation, a fixed consumer-map count, strict key inventory, and the old compression key. Dictionary/consumer drift remains a limitation, not proof of complete interface correctness.

This is a research baseline with disclosed debt. The present UI/R8 fixes do not repair those legacy mechanisms or make an all-green claim. Future work should test actual interfaces and semantic effects without restoring obsolete SC rules just to satisfy string assertions.

## Research boundaries

SC occurrence, completion, scope, persistence and adjudicative importance are separate judgments. In this branch, completion relevant to the principal dispute promotes the whole-debate mainline type; marginal completion remains local. This is a modeling choice, not a measured advantage.

Software checks establish only their stated properties. No new human-equivalence result, benchmark win, external adoption, archival DOI or accepted paper is claimed. Future evaluations should cover paraphrase stability, evidence-sensitive revision, repeated-reason inflation, partial contributions, model bias, failures and reader understanding.
