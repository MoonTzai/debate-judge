# Support and Governance

Debate-Judge is currently maintainer-led. Governance should reflect actual practice rather than imitate a large project.

## Development

Substantive public changes should be traceable through commits, tests, documentation, and issues/discussions where useful. Do not fabricate contributors, pull requests, issues, adoption, or backdated activity.

## Support

Bug reports and feature requests may use the GitHub issue tracker. Include the software version, environment, minimal reproduction, expected/observed behavior, and whether external model calls were involved. Never post API keys, private transcripts, or private adjudication artifacts.

## Decision authority

Software-integrity checks may fail closed on malformed artifacts or broken contracts. They must not mechanically erase semantically valid debate-analysis content merely because it violates an incidental presentation convention. Semantic and scientific questions require explicit review and evidence.

## Security and privacy

Treat credential exposure, personal-data leakage, and rights concerns as release blockers. Use private disclosure rather than a public issue when reporting sensitive material.
